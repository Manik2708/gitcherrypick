# Fixtures

Every integration test is data. No test hard-codes a request or an expected response — it
loads them from here, and the Go in `backend/e2e` is a runner, not a collection of cases.

Adding a test case means adding a directory. It does not mean writing Go.

## Layout

Mirrors the package structure it exercises:

```
fixtures/
  seed/                     shared database state, loaded before every case
  controllers/              exercised through the HTTP surface (stage 3, e2e)
    auth/       <case>.json
    claims/
    skills/
    evaluation/
    discovery/
    admin/
  services/                 stage 4 — unit-test fixtures, mocking repositories
```

`controllers/` is what the e2e suite runs. `services/` exists so the same convention
carries into stage 4 unit tests rather than a second one being invented then.

## A case

**One file. Request and expected response sit together on each step**, so a case reads top
to bottom as a conversation with the API and there are no two arrays to keep index-aligned.

```json
{
  "name": "submit a claim whose PR is not merged",
  "description": "Validation rejects it naming the specific item — ADR-0003.",
  "seed": ["principals", "catalogue", "repositories"],

  "steps": [
    {
      "as": "alice",
      "request": { "method": "POST", "path": "/claims", "body": {} },
      "expect": {
        "status": 201,
        "body": { "id": "<uuid>", "status": "draft", "version": 1 }
      }
    },
    {
      "as": "alice",
      "request": {
        "method": "POST",
        "path": "/claims/{{claim_id}}/evidence/prs",
        "body": {
          "prs": [{ "position": 1, "url": "https://github.com/acme/lib/pull/7" }]
        }
      },
      "expect": {
        "status": 422,
        "body": {
          "error": "invalid_evidence",
          "items": [{ "position": 1, "reason": "not_merged" }]
        }
      }
    }
  ]
}
```

`request` is hand-written. `expect` is generated by `-update` and then **reviewed** — that
is what makes this snapshot testing rather than assertion-writing, and it is why the two
live in separate keys even though they share a file: **`-update` rewrites only `expect`
blocks and never touches `request`, `name`, `description`, or a comment.**

### Fields

| Field                   | Meaning                                                                                                                            |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `name`                  | Human label. Becomes the Go subtest name.                                                                                          |
| `description`           | Why this case exists, and which ADR it encodes. **Required** — a fixture nobody can explain is a fixture nobody can safely change. |
| `seed`                  | Named seed sets from `seed/` to load. Empty means a bare database.                                                                 |
| `steps[].as`            | Which seeded principal authenticates the step. Omit for anonymous.                                                                 |
| `steps[].request`       | `method`, `path`, `body`, optional `headers`. `path` supports captures.                                                            |
| `steps[].capture`       | Explicit captures from the response, when the automatic rule is not enough.                                                        |
| `steps[].fake`          | Fake-adapter state for this step — GitHub responses, AI judgements, clock.                                                         |
| `steps[].expect.status` | HTTP status.                                                                                                                       |
| `steps[].expect.body`   | Full response body, after normalisation.                                                                                           |
| `steps[].expect.db`     | Optional. SQL assertions for state the API does not return — standing, link status, cooldown tier.                                 |
| Any `_`-prefixed key    | Comment. Ignored by the runner, preserved by `-update`.                                                                            |

## Captures

A step's response fields are available to later steps as `{{name}}`. Anything matching
`^[a-z_]+_id$` in a response body is captured automatically, so `{"id": "..."}` from a
create becomes `{{claim_id}}` in the next path.

Explicit capture when the automatic rule is not enough:

```json
{ "capture": { "share_token": "$.token" } }
```

## Normalisation

Values that differ every run are replaced before comparison, so `expected.json` stays
stable and reviewable:

| Real value                                     | Normalised to |
| ---------------------------------------------- | ------------- |
| Any UUID                                       | `<uuid>`      |
| RFC3339 timestamp                              | `<timestamp>` |
| Opaque token (refresh, share link, invitation) | `<token>`     |
| `duration_ms`, `input_tokens`, `output_tokens` | `<number>`    |

**Scores are never normalised.** They are the thing under test, and a rubric change that
moves them must show up as a failing snapshot — that is the point of pinning them.

Array order is compared as-is. An endpoint returning an unstable order is a defect in the
endpoint, not something the runner should paper over.

## The fakes

Every external dependency is an interface (ADR-0001), so the suite runs against fakes and a
**real Postgres**. No network, no rate limits, no spend, and the same result every run.

**GitHub** — `steps[].fake.github` supplies PR and repository responses keyed by
`owner/repo#number`. A fixture states the facts it needs; nothing is fetched.

**AI** — `steps[].fake.ai` supplies the judgement the model would have returned, in the
exact ADR-0007 contract shape. This is how disqualification, the quality floor, and
per-skill shares are tested deterministically.

**Clock** — `steps[].fake.clock` sets or advances time, which is the only way to test the
7-day claim lock, the 15-day availability expiry, lease expiry, and the escalating
re-evaluation cooldown without waiting.

## Running

```bash
backend/scripts/e2e.sh              # build, start Postgres, run
go test ./e2e/... -run TestFixtures/claims
go test ./e2e/... -update           # regenerate expected.json — REVIEW THE DIFF
```

`-update` is how a snapshot is created or changed. **A regenerated `expected.json` committed
without reading the diff defeats the entire method** — the suite will then assert that the
code does whatever it currently does, which is not a test.

## These fixtures must fail

Stage 3 is written before stage 4 exists. **Every case here is expected to fail right now**,
and a passing one means the fixture is wrong — asserting something no implementation
provides.

They turn green only through the implementation work in stages 4 and 5, and no implementer
may edit a fixture to make one pass. A fixture that seems wrong goes to the Planner.
